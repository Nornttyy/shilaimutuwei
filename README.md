# 史莱姆基地 · 可玩版

一个零依赖横屏游戏：经营持续白昼的史莱姆基地，派出恰好三只史莱姆进入东部软胶废土，自动战斗、选择路线和变异，最终击败 Boss 并把奖励带回基地。可直接在浏览器、GitHub Pages 和微信小游戏 Canvas 运行。

在线稳定版：<https://nornttyy.github.io/shilaimutuwei/>

## 运行

```bash
python3 -m http.server 8080
```

然后打开 `http://localhost:8080`。建议使用横屏或桌面浏览器。

## 发布到 GitHub Pages

生成可提交的 Pages 白名单包：

```bash
npm run build:docs
```

构建会同时读取 `assets/asset-spec.json` 和 `assets/rig-parts.json`，并严格检查两份清单引用的 PNG 完整结构；普通素材还会核对尺寸、透明通道和文件体积上限。`asset-spec` 当前精确声明 118 张正式游戏 PNG；骨骼清单另精确引用 8 张角色主图集和 8 张独立表情图集，共 16 张 rig PNG。主图集在运行时裁成身体、眼睛、嘴巴及必要的前后配件骨骼层，眼睛和嘴巴状态则从表情图集独立替换。

`npm run build:docs` 生成的 `docs/` 是 GitHub Pages 白名单包，只包含入口、完整游戏模块树、两份素材清单，以及清单精确引用的正式运行时 PNG。校对图、预览图、候选图、独立导出层、源图、旧素材和未被引用的图片不会进入发布包。缺少任何一张清单素材、相对模块引用失效或 PNG 元数据不符时，构建会列出具体路径并保留上一次成功产物。

构建通过后提交 `docs/` 并推送 `main`，再到仓库的 **Settings → Pages** 配置从 `main` 分支的 `/docs` 目录发布：

1. 将 **Source** 设为 **Deploy from a branch**。
2. 选择 **main /docs** 并保存。

此方案不需要 GitHub Actions 或额外的 workflow 权限。仓库当前使用 **main /docs** 发布；项目内全部使用相对资源路径，可直接运行在 `https://用户名.github.io/仓库名/` 这类子路径。

本地检查发布包时使用：

```bash
npm run build
python3 -m http.server 8080 --directory _site
```

## 微信小游戏构建

微信主包只放代码与素材清单，正式 PNG 通过 HTTPS 地址加载，避免把全部美术塞进主包。先发布 GitHub Pages，再生成可导入微信开发者工具的 `_wxgame/`：

```bash
WECHAT_ASSET_BASE_URL=https://nornttyy.github.io/shilaimutuwei node scripts/build-wechat.mjs
```

正式发布时可把这个地址替换为自己的 HTTPS CDN，并在微信公众平台配置合法下载域名。微信包的 `game.js` 会创建原生 Canvas、启动 `SlimeGame`、桥接触摸事件，并在切到后台/回到前台时暂停和恢复帧循环。未配置广告位或服务端支付时，相关商业能力保持关闭，不会在客户端误发奖励。

## 渲染与动画

- 公开入口固定加载生成的 PNG 分层骨骼素材；旧的 `?rig=vector` 参数在线上会被忽略，仅本机 `localhost` 调试时可临时启用。启动加载采用 15 秒单图超时、受控并发、一次失败重试和 20 秒前台等待上限，避免全部 90 张图片同时抢占连接或永远卡在加载页；一个角色的所有分层仍然必须完整到齐才会原子切换，分层延迟但生成版立绘已就绪时会优先显示立绘，只有相关图片全部不可用时才使用应急矢量绘制。
- 8 个角色目前共导出 51 个基础部件和 56 个眼睛/嘴巴状态，位于 `assets/generated-v2/rig-parts-exported/`；运行时仍使用图集合批加载，减少网络请求。泡泡的三颗装饰泡已拆成独立骨骼层，并只保留一层位于身体外侧的蓝环；壳壳采用后壳、身体、前壳与表情的稳定遮挡顺序，分层完成度与芽芽、亮钉一致。
- 4 名幸存者和 4 类敌人均已接入部件骨骼动画，覆盖待机、移动、攻击、受击、倒地与死亡状态；酸壳蜗王另有可被打断的蓄力状态。
- 战斗反馈使用逐帧 Canvas 动画：新绘制的命中星芒、冲击环、胶滴、泡泡、叶片、裂隙碎片、蜜胶、换位光团、尘团和彩带从透明 4×4 图集中独立裁切，再分别平移、旋转、缩放和错峰出现；缺图时保留程序化兜底，不使用整张特效图片淡出。每帧最多绘制 64 个图集部件，其中 12 个名额只留给清场、4 个留给技能；连锁死亡和连续击退会自动简化次要碎片。
- 骨骼定义、动作片段和播放器位于 `src/animation/`，视觉控制器不进入存档数据。

重新生成并检查当前分层素材：

```bash
npm run generate:expressions
npm run export:rig-layers
npm run review:rig
```

动作校对表输出到 `assets/generated-v2/rig-review-current/`，不会进入 Pages 发布包。

## 当前可玩内容

- 24×16 大地图与可平移、缩放镜头；方格只负责规则，地表视觉保持连续、自然。
- 持续白昼的基地经营；史莱姆自动采集、搬运、建造、修整和迎击连续弱怪群。
- 可采集、纯障碍、可破坏和不可破坏四类地形，以及基地花园和东部明亮废土两套外观。
- 4 名可分层动画的史莱姆、5 种建筑、4 张技能、3 件道具和动态逐帧特效。
- 三人远征：组队、三类路线、九种变异、大量弱怪、最终 Boss、战利品结算和安全中断恢复。
- 布局、资源与软晶本地保存；广告与支付适配已安全隔离，未配置时不影响游玩。
